## Troubleshooting

### Issue: "OCR returns minimal text or failed"

**Cause:** PDF quality too low or Tesseract not initializing

**Solutions:**
1. Try a different PDF with better scan quality
2. Check Railway logs for Tesseract initialization errors
3. Verify internet connection (language pack downloads from CDN)
4. Wait 30 seconds for Tesseract worker to initialize fully

### Issue: "No images generated by pdf2pic"

**Cause:** PDF conversion failing

**Solutions:**
1. Verify PDF is not corrupted (open in Adobe Reader first)
2. Check if PDF is actually an image (not digital/text PDF)
3. Ensure PDF file size is reasonable (<20MB)

### Issue: "Tesseract worker initialization failed"

**Cause:** Language pack download timeout or network issue

**Solutions:**
1. Refresh the page and try again
2. Check Railway network connectivity
3. Wait a few minutes and retry (CDN might be slow)

## FAQ

**Q: How long does OCR take per file?**  
A: 10-20 seconds depending on PDF complexity and current server load.

**Q: Why does it need to download language pack?**  
A: Tesseract.js downloads Indonesian language data from CDN on first use. This is cached for future requests.

**Q: Can I process multiple files at once?**  
A: Yes, up to 25 files. They process sequentially (one after another) to avoid server overload.

**Q: What if the invoice number has letters or special characters?**  
A: The extraction pattern looks for 12-15 digit numbers. Mixed alphanumeric might not extract. Check logs to see extracted text.

**Q: Will this work on all PDF types?**  
A: Yes, if they're scanned images. Digital PDFs (text-based) will use normal text extraction first, then OCR as fallback.
